# Rampage 产品定义

## 文档定位

本文是产品文档的第一层，只定义 `Rampage` 的目标用户、价值、玩法边界和成功标准，不展开源码接口。继续阅读时，按以下路径下钻：

1. [PRD](./PRD.md)：F001 至 F007 的规则、验收标准、依赖、风险与逐功能证据。
2. [UE 交互规格](./UE-spec.md)：原生游戏界面、信息职责、关键流程与逐界面证据。
3. [变更日志](./changelog.md)：产品决策与 Git 谱系记录。
4. [Sprint：项目知识基线](../sprints/sprint-documentation-baseline.md)：跨角色文档建设范围。

本文使用三种证据标签：

- **事实**：可由仓库代码、XML、资源、构建文件或 Git 历史直接支持。
- **产品定义**：对最终游戏体验的规范性约束。
- **未知**：仓库静态材料不足以证明，必须在兼容的 Windows 游戏环境中确认。

## 产品一句话

**产品定义**：Rampage 是建立在《Sid Meier's Civilization IV: Beyond the Sword》和 Fall from Heaven 2 基础内容之上的回合制奇幻战术覆盖包，以元素氏族、可读的多轮掷骰战斗、无视视线的远程打击、基于回合起点的 `plotDistance` 移动半径、地块驻军容量、工人占格生产和玩家级食物军费为核心体验。

这里的 `plotDistance` 按 `max(dx, dy) + floor(min(dx, dy) / 2)` 计算；它在 Civ4 地块网格上的半径边界近似八边形，而不是欧氏圆。

## 用户问题

传统 Civilization IV / Fall from Heaven 2 战斗把大量结果压缩在单一战斗强度与生命比例中，玩家不容易从单位面板直接判断“能打几次、每次可能造成多少伤害、为什么命中或落空”。同时，单位移动、驻军堆叠与经济供养彼此联系较弱。

Rampage 将这些决策变成可观察、可计算的战术取舍：单位由生命、护甲、敏捷、近战攻击次数、远程距离与远程攻击次数共同定义；地块容量约束集中堆叠；工人驻留把地图产出转成玩家级收入；军队规模持续消耗玩家级食物。

## 目标用户

### 主要用户

- 熟悉 Civilization IV 回合制操作、愿意学习数值化战斗规则的奇幻策略玩家。
- 能在 Windows 环境安装 Beyond the Sword、Fall from Heaven 2 Patch o 基础内容及覆盖包的模组玩家。
- 偏好小规模元素氏族对抗、重视单位编成、位置和后勤约束的玩家。

### 次要用户

- 需要从 XML 调整数值、从 Python 调整界面与事件、从 C++ DLL 调整规则的模组维护者。
- 需要用可重复战斗与经济场景验证规则的测试者。

## 价值主张

1. **每次攻击可解释**：命中率来自目标敏捷及修正，伤害受攻击强度与目标护甲影响，攻击次数决定单次交战内的掷骰次数。
2. **远程单位有明确射程角色**：最小距离、最大距离、远程强度和射击次数共同区分弓兵与攻城单位；射击不受视线阻挡。
3. **位置本身是资源**：单位每回合不能通过绕路突破基于回合起点的 `plotDistance` 位移半径，地块容量又限制可驻留单位成本。
4. **工人与军队处于同一经济闭环**：工人占据合格地块贡献食物与商业，军事单位消耗玩家级食物，缺口进一步损失金币。
5. **关键数值出现在原生游戏界面**：主 HUD、单位面板、战斗预览、战斗日志、财务顾问和文明百科共同解释规则。

## 核心体验循环

1. 在游戏设置中选择 Air、Earth、Fire 或 Water 氏族。
2. 探索地图，并在单位回合起点的 `plotDistance` 半径、地形移动成本和目标地块容量之间规划路线。
3. 将工人部署到合格地块，以地块食物与商业产出支撑玩家级储备。
4. 依据单位生命、护甲、敏捷、攻击强度与攻击次数选择近战或远程交战。
5. 通过战斗预览与日志核对命中、落空、伤害和剩余生命。
6. 在财务顾问与主 HUD 中平衡食物收入、军事食物成本和金币风险。

## 核心能力清单

| 功能 ID | 能力 | 玩家价值 |
|---|---|---|
| F001 | 外部运行依赖与元素氏族游戏入口 | 在正确基础安装上进入聚焦的四氏族对局 |
| F002 | 多属性、多次掷骰的近战 | 以单位特性和战斗预览做出可解释的攻击决策 |
| F003 | 带最小/最大距离的远程打击 | 用弓兵和攻城单位进行位置化火力投送 |
| F004 | 基于回合起点的 `plotDistance` 移动半径与地块容量 | 阻止绕路超程和无限堆叠，强化阵地规划 |
| F005 | 工人占格生产 | 用工人部署把地块产出接入玩家经济 |
| F006 | 玩家级食物经济 | 让军队规模受到持续后勤成本约束 |
| F007 | 原生界面的信息与反馈 | 在不离开游戏的情况下理解单位、战斗和经济 |

## 内容边界

### 产品范围

- `Rampage/` 是产品规则与内容的权威代码线。
- 四个可选元素氏族：Air、Earth、Fire、Water；Barbarian 由游戏系统使用，不作为玩家可选氏族。
- XML 定义的单位、科技、建筑、改良、晋升和法术只有在其引用链完整且被 Rampage 玩法入口使用时，才进入产品承诺。
- DLL、XML Schema、XML 数据、Python 入口和美术/字体资源共同构成一个不可拆分的运行契约。

### 外部依赖

**事实**：仓库只提供覆盖到外部 `Mods\Rampage\Assets` 的规则、界面、资源与 DLL 文件；基础 Python 模块和美术并不完整随包提供。Git 起点标注 “FFH2 Patch o”。

**产品定义**：Rampage 是覆盖包，不是独立游戏，也不是完整模组发行物。受支持的运行前提是：

1. Windows 上可运行的 Civilization IV: Beyond the Sword；
2. 可供继承的 Fall from Heaven 2 Patch o 基础内容与 Python/美术资源；
3. 名为 `Rampage` 的模组目录；
4. 覆盖包中的 DLL、XML、Python、Art 和 res 保持同一套契约。

**未知**：仓库不能证明任一用户机器上的基础安装内容、目录布局、加载顺序或实际加载的模组名称。

### 谱系边界

**事实**：Git 历史依次出现 `Fall from Heaven 2`、`Streak`、`Streak 3` 和 `Rampage`。Rampage 的后续提交集中演化战斗、远程、移动/容量、工人与食物机制。

**产品定义**：前三个目录用于追溯来源与对照，不作为 Rampage 的并行运行目标，也不要求跨目录同步功能。

### 遗留内容边界

**事实**：场景、事件与单位类别中保留了源自基础内容的引用，其中部分文明或单位类型不属于 Rampage 的四元素氏族与精简单位集合。

**产品定义**：这些场景、事件和引用残留不自动构成可玩内容。只有同时满足类型引用完整、外部基础资源可解析、游戏入口可达且 Windows 运行验收通过的条目，才可以被纳入产品承诺。

## 明确不做

- 不把仓库包装成不依赖 Beyond the Sword / Fall from Heaven 2 的独立程序。
- 不承诺 macOS 或 Linux 能直接运行 Windows 游戏和 32 位 DLL。
- 不把 `Fall from Heaven 2`、`Streak`、`Streak 3` 当成需要共同交付的四套产品。
- 不默认宣称遗留场景、随机事件、法术或单位类别全部可用。
- 不设计 Web 页面、HTTP 路由、账号系统、云存档或关系数据库。
- 不把非英语占位文本视为完整本地化；自定义核心文案的可验证语义以英语文本为准。

## 产品成功标准

成功通过兼容 Windows 游戏环境中的可重复场景判断：

- 四个元素氏族均可从游戏设置进入普通对局。
- F002 至 F006 各至少有一个正常场景、一个边界场景和一个拒绝/缺口场景可被观察。
- 近战预览与战斗日志中的命中、伤害、攻击次数和生命变化能够相互对账。
- 远程攻击在最小与最大距离边界可执行，越界或无合法防守者时不可执行，地形视线阻挡不改变合法性。
- 同一回合内无法通过曲折路径到达超出回合起点 `plotDistance` 半径的地块；容量不足的友方地块拒绝继续驻入。
- 首名工人进入合格地块后，玩家食物/商业收入按地块产出变化；重复工人不重复计入；最后一名工人离开后贡献撤销。
- 玩家级食物收入、军事食物成本、净变化、储备与食物缺口对应的金币损失能够在 HUD、财务顾问和回合结算中对账。
- 每条产品验收标准能反向定位到一个 F 编号和一个仓库证据位置。

## 未知项

下列内容是静态证据差距引出的运行未知，不构成游戏内复现结论：

- 可重复加载覆盖包的基础安装、补丁组合与目录布局。
- 预编译 DLL、源代码和外部基础全局定义是否组成同一套运行行为。
- 玩家级 Food Stores 与每回合修正在保存/重载后的保留行为，以及非零每回合修正的运行来源。
- 禁用研究是否应同时把 `COMMERCE_FOOD` 商业收入归零。
- 运输货物成本是否实际影响地块容量拒绝。
- 城市训练资格是否计入候选单位成本，以及训练后等于或超过容量边界的行为。
- 防守方先致死攻击方时，近战是否仍产生同轮反击，以及是否符合“死亡立即停止”目标。
- `Work Tile` 的地块标记、Worker 位置和玩家商业账本在保存/重载后的状态一致性，以及完成态边界表现。
- 遗留场景、事件、法术和引用残留的安全可达集合。

逐项责任人与验证问题见 [PRD：开放问题](./PRD.md#开放问题)。
