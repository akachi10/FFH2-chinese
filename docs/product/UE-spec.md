# Rampage UE 交互规格

## 文档定位

本文描述玩家在 Civilization IV 原生客户端内可观察的界面入口、信息职责与关键流程，不定义 Web 页面或 HTTP 路由。功能与验收标准见 [PRD](./PRD.md)，产品边界见 [产品定义](./product-definition.md)，文档记录见 [变更日志](./changelog.md)。

## 交互原则

1. **先给决策信息，再提交不可逆动作**：近战预览先展示命中、伤害、次数与生命；远程模式先过滤合法目标。
2. **同一字段只表达一种含义**：生命、护甲、近战强度、近战次数、远程强度、远程次数、食物收入和食物成本不得互相替代。
3. **结果可追溯**：战斗结果必须能从逐次日志复核；食物结算必须能从 HUD 与财务顾问复核。
4. **地图直接表达空间规则**：移动、射程、容量和工人占格都通过地块选择与单位位置发生，不引入独立管理页面。
5. **外部依赖显式**：进入这些界面之前，玩家必须在兼容 Windows Beyond the Sword + FFH2 基础安装中加载 Rampage。

## 原生界面入口

| 入口 | 到达方式 | 主要职责 | 关联功能 |
|---|---|---|---|
| 游戏设置 | 从 Beyond the Sword 加载 Rampage 后进入单人游戏设置 | 选择 Air、Earth、Fire 或 Water 氏族及原生地图参数 | F001 |
| 主地图与 HUD | 对局开始后常驻 | 地块、单位、城市、玩家食物储备与净变化 | F004、F005、F006、F007 |
| 选中单位面板 | 在主地图点击己方单位 | 显示生命、护甲、近战强度 × 次数、移动力和可用动作 | F002、F003、F007 |
| 近战目标预览 | 选中可攻击单位并把指针移到/指向敌方地块 | 显示双方命中概率、伤害、攻击次数和生命 | F002、F007 |
| 远程目标模式 | 选中具备远程能力的非空中单位，点击远程动作或使用其上下文快捷键 | 高亮/选择合法目标地块并提交远程动作 | F003、F007 |
| 战斗日志 | 交战时由原生战斗消息系统写入 | 逐次显示命中、落空、骰值、门槛、伤害、剩余生命和击败 | F002、F003、F007 |

| Worker 动作栏 | 在主地图选中 Worker | 提供移动、建造及条件满足时的 `Work Tile` 动作 | F005 |

## 界面导航关系

- 游戏设置 → 选择元素氏族 → 主地图与 HUD。
- 主地图 → 选中单位面板 → 近战目标预览 → 提交移动攻击 → 战斗日志。
- 主地图 → 选中远程单位 → 远程目标模式 → 选择合法敌方地块 → 战斗日志。
- 主地图 → 选中 Worker → 移入合格地块 / 使用 `Work Tile` 上下文动作 → HUD 与财务顾问数值变化。
- 主地图 → 财务顾问 → 查看食物储备、收入与成本 → 关闭后返回主地图。
- 主地图或百科入口 → 文明百科单位页 → 查看单位完整静态属性 → 返回先前界面。

## 游戏设置

### 信息与控件

- 文明选择列表展示 Air Clan、Earth Clan、Fire Clan、Water Clan。
- Barbarian 不作为玩家选项。
- 地图、速度、难度等其余控件沿用原生游戏设置；Rampage 不定义独立启动器。

### 异常边界

- 基础安装缺少 Python 模块、美术资源或全局定义时，仓库没有可确认的专用错误页；此类问题属于加载/安装故障，而非游戏内业务空态。
- 遗留场景文件不作为普通设置中的可靠入口；任何场景入口必须先通过引用与运行验收。

## 主地图与 HUD

### 常驻信息

- 玩家级食物图标、Food Stores 数值和正/负每回合变化。
- 原生金币、研究、回合、地图和城市信息。
- 地图上的单位堆叠、Worker 所在地块、城市与改良视觉。

### 食物显示规则

- 正变化使用正向每回合格式，负变化使用负向格式。
- HUD 的玩家级食物不得与城市粮仓/人口增长条混为一项。
- 储备结算不得显示负数跨回合保留；缺口按 F006 转换为金币损失后归零。

### 未知

- 食物 HUD 使用了原生金币每回合文本模板，最终本地化措辞与符号需运行确认。
- 仓库不能证明在所有分辨率和界面缩放下，FoodText 与 GoldText 不重叠。

## 选中单位面板

### 信息层级

1. 单位名称与原生状态。
2. 生命与护甲：受伤时显示 `当前生命/最大生命`，满生命时显示当前生命；护甲并列显示。
3. 近战强度：使用 `强度 × 攻击次数`，不得按剩余生命折算强度。
4. 移动力与原生晋升/动作。
5. 具备远程能力时，动作栏提供远程目标模式；详细远程静态数值由百科和单位帮助文本承担。

### 状态

- **可操作**：单位具有剩余行动资格，动作按钮按合法性出现。
- **战斗中**：未知的即时强度位置可用 `?`，但静态强度和次数仍保持单位定义。
- **受伤**：生命显示当前值与上限；近战强度不因生命比例下降。
- **无远程能力**：不提供远程目标模式。

## 近战交互流程

### 流程

1. 玩家选中可攻击单位。
2. 玩家把攻击意图指向敌方防守者所在的相邻地块。
3. 目标预览显示：
   - 攻击方对防守方的单次命中概率、单次伤害、攻击次数、目标当前生命；
   - 防守方对攻击方的对应反击信息；
   - 双方当前/最大生命。
4. 玩家提交移动攻击。
5. 战斗按双方攻击次数交替处理掷骰，任一方死亡即停止。
6. 攻击方剩余移动力归零。
7. 战斗日志逐次写入骰值、命中门槛、命中/落空、伤害、剩余生命和击败信息。

### 拒绝条件

- 目标不可进入、不是敌方合法防守者、外交状态不允许攻击或空间规则拒绝时，不提交近战。
- 若玩家尝试通过曲折路径到达回合起点 `plotDistance` 半径外的目标，目标仍不可进入。

## 远程交互流程

### 动作入口

- 当选中单位满足“非空中、远程最大距离大于 0、远程强度大于 0、可战斗”等条件时，远程目标模式可用。
- XML 为该模式声明可见、带高亮的原生目标模式和 `B` 键；同键也用于 Worker 的 `Work Tile`，因此必须按所选单位与可用动作上下文解释。

### 流程

1. 玩家选中远程单位。
2. 玩家点击远程动作，进入远程目标模式；光标使用原生空袭式目标光标。
3. 系统只接受以下地块：
   - 距离不小于单位最小距离；
   - 距离不大于单位最大距离；
   - 地块上存在合法敌方防守者。
4. 视线阻挡不从合法集合中移除目标。
5. 玩家点击合法目标。
6. 系统按远程攻击次数逐次掷骰；命中造成远程伤害，落空不造成伤害，死亡停止剩余射击。
7. 攻击单位剩余移动力归零，日志显示逐次结果。

### 拒绝状态

- 目标过近、过远、为空或没有合法防守者：不提交动作。
- 单位不具备远程能力：远程目标模式不可用。
- 单位已经进行不允许重复的攻击且没有对应例外：远程目标模式不可用；具体重复规则受外部全局定义影响，需运行确认。

## 移动与容量交互

### 基于回合起点的 `plotDistance` 移动半径

1. 新回合开始，单位所在地成为回合起点。
2. 玩家规划直线或曲折路径。
3. 每一步同时接受原生移动成本与“目标和回合起点的 `plotDistance` ≤ 最大移动格数”检查。
4. 任何超出该 `plotDistance` 边界的目标都不可进入；剩余移动点不能绕过该限制。
5. 进入敌方相邻控制区后，单位结束移动。

### 地块容量

1. 玩家把单位移动到已有友方单位的地块。
2. 系统按地形、地物、改良、丘陵、城市与人口计算容量，并按单位地块成本累计占用。
3. 加入后不超限则移动；超限则单位留在原地。
4. 成本为 0 或不能防守的单位不因容量被拒绝。

### 反馈边界

- 仓库可确认的反馈是“移动不发生/动作不提交”。
- 仓库未提供可确认的常驻容量数字、剩余容量条或专用超限文案；不得在验收中假设这些控件存在。
- 城市训练列表受容量检查影响，但等值边界和生产队列反馈需运行确认。

## Worker 占格交互

### 流程

1. 玩家选中 Worker。
2. 对满足科技与地块条件的目标，Worker 动作栏可出现 `Work Tile`；按钮文本为 “Work Tile”，说明语义为“Assigns worker to work plot”。
3. 玩家把首名 Worker 移入合格地块。
4. 地块标记为被工作；该地块的食物进入玩家食物商业，商业进入玩家金币商业。
5. HUD 和财务顾问刷新。
6. 第二名同类型 Worker 进入同一地块时不重复增加产出。
7. 部分 Worker 离开但仍有同类型 Worker 驻留时，产出保持。
8. 最后一名 Worker 离开时，产出撤销，地块不再标记为被工作。
9. Worker 在地块上改变改良/产出时，界面只展示重算后的新值。

### 状态与边界

- **不合格地块**：不产生占格收入。
- **首名 Worker**：产生一次收入贡献。
- **重复 Worker**：不重复贡献。
- **最后离开**：撤销贡献。
- **建造中**：执行建造会结束 Worker 本回合移动。
- `Work Tile` 的长建造时长、完成后的改良视觉、存档恢复和离格撤销属于运行确认项。

## 玩家级食物交互

### 财务顾问布局职责

- `Food Stores`：玩家级食物储备。
- `Food Income`：玩家食物商业收入。
- `Food Cost`：军事单位数与额外单位成本形成的食物支出。
- 金币收入/支出继续使用原生区域；食物三项不应被计入金币小计。

### 回合结算流程

1. 玩家在 HUD 查看食物储备和预计净变化。
2. 玩家打开财务顾问，核对 Food Income 与 Food Cost。
3. 回合结束时，系统执行 `储备 + 收入 - 成本`。
4. 结果不低于 0：保留为新储备。
5. 结果低于 0：每个缺口扣 5 金币，食物归零。
6. 下一回合 HUD 与财务顾问显示结算后的值。

### 特殊状态

- 无政府、禁用生产或“无维护”游戏选项下，Food Cost 显示/计算为 0。
- 食物缺口不以城市人口饥饿提示或自动解散单位替代；用户应从金币变化与食物归零观察后果。
- 仓库未提供可确认的专用“食物缺口扣金”弹窗或消息，不能把弹窗作为必要验收条件。

## 文明百科单位页

### 信息职责

- 最大生命与生命图标。
- 护甲与防御图标。
- 近战强度 × 近战攻击次数。
- 若远程强度非零，显示远程强度 × 远程攻击次数和远程图标。
- 移动力、生产成本及原生单位说明。

百科负责解释单位静态定义；主地图选中面板负责显示该单位实例的当前生命与行动状态。

## 战斗日志

### 单条命中

- 行动方/承伤方名称。
- 伤害值。
- 承伤后当前生命与最大生命。
- 本次骰值与所需门槛。

### 单条落空

- 行动方/目标名称。
- 本次骰值与所需门槛。
- 不增加伤害。

### 击败

- 当任一方生命不高于 0 时，追加击败消息。
- 近战与远程使用相同的 `combatLogCalc`、`combatLogHit`、`combatLogMiss` 事件语义。

## 文案与本地化

- 自定义规则的仓库证据以英语文案为语义基准，例如 `Work Tile`、`Food Stores`、`Food Income`、`Food Cost`。
- 多个非英语字段使用与功能无关的占位文本；这些字段不构成准确翻译承诺。
- 图标字体由 `GameFont.tga` / `GameFont_75.tga` 提供远程与食物相关符号；字体资源必须与 XML/Python/DLL 同步部署。

## 可访问性与可读性约束

- 不只依靠颜色区分命中/落空、正/负食物变化；文字或正负号必须同时存在。
- 强度必须同时显示数值与攻击次数，远程数值使用独立图标。
- 日志必须保留文字化骰值、门槛和伤害，以便颜色辨识困难的玩家复核。
- 数值不能被地图动画遮蔽为唯一反馈；动画结束后仍可从日志读取结果。
